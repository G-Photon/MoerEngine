# Raster 环境光

Raster 的 Image Based Lighting（IBL）使用当前 skybox 作为远处环境，在延迟光照中加入漫反射与镜面反射。入口在渲染设置的 `Image Based Lighting`：`Enable IBL` 控制开关，`IBL Intensity` 控制强度。默认关闭，强度为零时不采样 IBL。

## 环境资源

在根目录 `MoerEngine.toml` 中设置：

```toml
[engine.render.raster]
skybox_path = "Skybox/WaterScene"
```

相对路径以编辑器资源的 `textures/` 目录为根，也支持绝对路径。目录内必须有 `posx.jpg`、`negx.jpg`、`posy.jpg`、`negy.jpg`、`posz.jpg`、`negz.jpg`，分别对应立方体的 +X、-X、+Y、-Y、+Z、-Z 面。六张图片必须是尺寸相同的正方形。修改 TOML 后重新启动编辑器。

JPEG 使用 sRGB 格式上传，由纹理采样执行到线性颜色的转换。因此，和以前把 JPEG 字节直接当线性颜色的 UNORM 方式相比，skybox 的颜色也会改变。丢失、损坏、非正方形或尺寸不一致的面会在创建立方体和记录上传命令之前报错，错误包含文件路径。

目前配置入口支持六面 JPEG 环境，不支持直接加载 `.hdr` 或 `.exr` 等经纬度环境图。内部卷积输出使用浮点纹理，测试也覆盖了大于 1 的线性 HDR 输入；这不代表文件加载器已经支持 HDR 文件。

## 光照与资源边界

第一次开启 IBL 时，`LightingPass` 持有的 `IblEnvironment` 为环境生成三个资源：

- 32×32 漫反射立方体，存储 irradiance / pi；使用余弦加权采样。
- 128×128 镜面立方体，8 级 mip，对应从 0 到 1 的粗糙度；使用 GGX 预过滤。
- 128×128 的 BRDF 积分 LUT，存储 split-sum 的两个系数，与环境内容无关。

材质的法线决定漫反射方向，视线反射方向和粗糙度决定镜面采样。材质金属度、基色和 AO 参与光照计算。它与直接光、Probe GI 和手动添加的环境光相加，因此同时开启时会叠加间接光照，调节场景时需要注意强度。

输入立方体按图形队列的 Sampled 边界交接；预计算通过现有 RDG 声明输入采样、逐面逐 mip 输出，并把结果导出为同一队列的 Sampled 状态。先提交卷积图，再让后续帧引用结果。Executor 的 FIFO、图形队列的有序提交与 RDG 导出屏障共同保证写后读依赖；命令引用保护在途纹理。因此这里不等待 CPU 观察到 GPU 完成，也不新增预计算完成状态。`FlushGPU` 只请求提交。第一次开启或替换环境时仍有 CPU 建图和 GPU 卷积成本，可能延迟该帧完成。

同一个不可变源纹理复用卷积结果。替换源纹理时重建环境相关立方体，复用 BRDF LUT；原地修改源纹理不是此缓存的更新协议。关闭后保留缓存，再开启不重新卷积。每帧光照参数持有纹理引用，RDG 声明三个资源的 sampled read；已有提交与完成机制负责在 GPU 使用结束后回收引用。

IBL 不包含局部探针、视差修正或局部可见性，不能替代场景 GI，也不会根据 skybox 的显示曝光校正自动改变光照强度。预过滤固定使用 256 个样本，极亮且很小的光源仍可能需要更高采样数或更完善的环境 mip 采样策略。

## 验证

构建 `TestIblLighting`，在可运行 Vulkan 的环境及编辑器输出目录内执行。默认数值测试检查恒定 HDR 与黑环境、六面和全部 mip、方向渐变环境、漫反射解析结果、CPU BRDF 参考积分、金属与非金属材质、粗糙度端点、AO 为零、缓存及源替换、相对与绝对资源路径、sRGB 解码和错误资源拒绝。

`TestIblLighting --scene` 使用 TOML 中的场景，依次检查关闭、开启、零强度、不同强度、关闭和重新开启，完成 144 个场景就绪帧后退出。这是集成和生命周期测试，不是截图质量判定。设置 `MOER_SHADER_GPU_TESTS=ON` 时，默认数值测试也注册为 CTest 的 `IblLighting`。
